\label{chap:intro}

Type systems are a powerful tool which can be used to ensure the absence of some runtime errors, which would otherwise require extensive testing or program analysis. Essentially, type systems form a set of rules which limit the programs that can be written in a given language. Most traditional compiled imperative languages, such as C and Java, have type systems that avoid some common programming errors, such as passing a string to a function that expects an integer. Although such programs in a weakly or dynamically typed language such as Python or JavaScript would compile and run, they would likely fail at runtime, whereas in a strongly typed language, the compiler would catch the error at compile time. One extra benefit of strongly typed languages is that the type system can be used to provide more information about the behavior of the code to the compiler, opening up new optimization paths.

Some languages take this concept further, by using the type system to enforce stronger properties of the code. For example, Rust \cite{Matsakis:2014} uses an affine type system to enforce memory safety, and absence of data races and dangling pointers, which are common source of bugs in C and C++ programs, without the need for a garbage collector. However, Rust still does not guarantee that concurrent programs are deadlock-free, as it does not have a type system that enforces communication protocols.

Session types \cite{Honda:1993,Honda:1998} have been used to enforce correctness in communication protocols, namely in languages based on process calculus, which model concurrent systems \cite{Milner:1980,Milner:1992:1,Milner:1992:2}. By coupling session types with linear logic \cite{Girard:1987,Caires:2010}, it has been possible to additionally guarantee deadlock freedom. CLASS \cite{Rocha:2022}, is an example of a session-typed language, built on top of the correspondence between session types and linear logic, that provides these guarantees. In fact, CLASS is the first language to simultaneously guarantee memory safety and the absence of dead-locks. The original CLASS interpreter implemented by Rocha et al. \cite{Rocha:2021:artifact} served as a proof of concept for the language. It wasn't optimized for performance, and thus, it wasn't suitable for real-world applications.

The Linear Session Abstract Machine (SAM) \cite{Caires:2024} is an abstract machine that allows for the sequential execution of session-typed languages such as CLASS through the use of buffered communication channels. Caires et al. expanded the existing CLASS interpreter with this new scheme \cite{Caires:2024:artifact}. This permitted a great increase in performance, as the overhead of spawning threads is very high in modern systems, and thus it is not feasible to spawn threads for every parallel process in a session-typed program, as most threads end up executing few instructions and spend most time waiting for communication. However, the SAM still does not make use of the properties of the source language to generate efficient machine code, as it is a high-level abstract machine.

\section{Work Objectives}

This project aims to design and implement a compilation scheme that translates the session-typed language CLASS into a low-level imperative language, such as C, while maintaining all of the safety and liveness guarantees of CLASS. This approach will allow the execution of CLASS programs possibly in orders of magnitude more efficient manner than the SAM interpreter, as the compiler will have extensive knowledge of the compiled programs. The SAM interpreter, on which the compiler is based, currently has no support for the affine sessions, reference cells and shared state features of CLASS. Instead, it covers only the pure fragment of the language. In this work, we aim to support all of the features of CLASS in the compiled programs, including the aforementioned ones.

The base CLASS language will also be extended with interoperation features with C, allowing programs to interact with the C standard library and other C programs. This will allow for the creation of more complex programs, which will be helpful to measure the real-world performance of the compiled programs. With this thesis, we also aim to use the properties guaranteed by the source language to optimize the target code in a way that is not possible for commonly used programming languages. We will compare the performance of the compiled programs with the original CLASS interpreter, the SAM interpreter, and with equivalent programs written in other languages, such as Haskell, Rust and C.

Finally, it is worth mentioning that we're planning on publishing a paper based on the results of this project, which will be submitted to a conference or journal in the area of programming languages or compilers.
